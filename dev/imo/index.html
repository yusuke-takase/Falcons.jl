Instrument database and parameter files

Reading an IMO

Falcons reads instrument models (IMO) in the flat-file layout used by litebird_sim (via libinsdb): a schema.json with entities, quantities, data files and releases.

using Falcons

imo = Imo("/path/to/imo")                               # directory containing schema.json
rel = "/releases/<tag>/satellite"

scan = SpinningScanningStrategy(imo, "$rel/scanning_parameters")
inst = InstrumentInfo(imo, "$rel/<telescope>/instrument_info")
ch = FreqChannelInfo(imo, "$rel/<telescope>/<channel>/channel_info")
det = DetectorInfo(imo, "$rel/<telescope>/<channel>/<detector>/detector_info")

query accepts the same identifiers as Imo.query in litebirdsim: release paths (the /releases prefix is optional), UUID strings, and `/datafiles/,/quantities/,/entities/or/format_specs/followed by a UUID. Only uncompressedschema.jsonfiles are read; decompressschema.json.gz` first.

If a release holds several versions of a quantity, Falcons returns the one with the latest upload_date (compared as ISO 8601 strings) and throws an ArgumentError if two versions share that date; litebird_sim returns any one of them.

The constructors mirror litebirdsim's `fromimo/fromdict: angles stored in degrees are converted to radians,FreqChannelInfoderives missing NETs and detector names, and unknown keys are ignored. A time-dependent detector quaternion is a dictionary withstarttime(seconds),samplingratehzandquats`; calendar start times are not supported. Unlike litebird_sim:

  • pixel and squid are stored as integers and no default bandpass is synthesised;
  • a JSON null is treated as a missing key, so the field keeps its default (litebird_sim fails on most of them); a null detector quaternion raises an ArgumentError;
  • FreqChannelInfo from a dictionary without channel is named "<bandcenter_ghz> GHz" (litebirdsim's `fromdictnames it"0.0 GHz"), and missing detector names are generated (litebird_sim'sfrom_dict` requires them unless the channel has a single detector).

Lists of detectors

detector_list_from_parameters builds detectors from dictionaries with litebirdsim's keys. As in litebirdsim, num_of_detectors_from_channel takes the first detectors of the channel, or all of them if the channel has fewer (a negative number raises an ArgumentError):

dets = detector_list_from_parameters(imo, [
    Dict("channel_info_obj" => "$rel/<telescope>/<channel>/channel_info",
         "num_of_detectors_from_channel" => 4),
    Dict("detector_info_obj" => "$rel/<telescope>/<channel>/<detector>/detector_info",
         "fwhm_arcmin" => 30.0),                        # fields override the IMO values
    Dict("name" => "mock", "sampling_rate_hz" => 19.0),
])

Parameter files

run_h_maps_pipeline reads a TOML file whose sections follow litebirdsim's names, computes the h-maps of the detectors and saves them with [`saveh_maps`](@ref):

[simulation]
base_path = "output"
start_time = 0.0
duration_s = "1 year"            # seconds, or "N years/days/hours/min/s"

[imo]
flatfile_location = "/path/to/imo"

[scanning_strategy]
imo_url = "/releases/<tag>/satellite/scanning_parameters"
# delta_time_s = 2.0             # optional: litebird_sim's interpolation

[instrument]
imo_url = "/releases/<tag>/satellite/<telescope>/instrument_info"

[hwp]
ang_speed_radpsec = 4.817        # 2π · rpm / 60

[[detectors]]
channel_info_obj = "/releases/<tag>/satellite/<telescope>/<channel>/channel_info"

[h_maps]
nside = 128
n_m_couples = [[0, 0], [2, 0], [4, 0], [2, -4], [2, 4]]
output_coordinate_system = "Galactic"
output_directory = "h_maps"      # relative to base_path
res = run_h_maps_pipeline("params.toml")

The scanning strategy and the instrument can also be given explicitly (spin_sun_angle_rad, precession_rate_hz, spin_rate_hz; spin_boresight_angle_rad, spin_rotangle_rad, boresight_rotangle_rad) instead of imo_url.
