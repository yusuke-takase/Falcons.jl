API reference

Falcons — Module
Falcons

Fast pointing, hit-map and h-map (spin-moment) computation for spinning CMB satellites, with the conventions, types and names of litebird_sim.

Main entry points:

  • Scan description: SpinningScanningStrategy, InstrumentInfo, DetectorInfo, IdealHWP, Observation, satellite_preset, detector_quat, split_observation.
  • Rotations: Quaternion, RotQuaternion (constant or sampled in time, e.g. an external attitude), quat_rotation.
  • Pointings: get_pointings, get_pointing_pixels, get_hitmap.
  • h-maps: make_h_maps, HMapsResult, save_h_maps, load_h_maps_from_file.
  • Instrument database: Imo, query, DetectorInfo(imo, url) and the other (imo, url) constructors, detector_list_from_parameters.
  • Parameter files: run_h_maps_pipeline.

Scan description

Falcons.SpinningScanningStrategy — Type
SpinningScanningStrategy(; spin_sun_angle_rad, precession_rate_hz, spin_rate_hz)

Scanning strategy of a spinning spacecraft whose spin axis precesses around the anti-Sun direction, as SpinningScanningStrategy in litebird_sim.

  • spin_sun_angle_rad: angle α between the spin axis and the anti-Sun direction.
  • precession_rate_hz: precession frequency (rotations per second).
  • spin_rate_hz: spin frequency (rotations per second).

The spin-to-Ecliptic rotation at the absolute time t (s) is

Rz(Ω t) · Rx(2π f_prec t) · Ry(π/2 − α) · Rz(2π f_spin t)

with Ω = Falcons.YEARLY_OMEGA_SPIN_HZ; see spin_to_ecliptic.

Falcons.InstrumentInfo — Type
InstrumentInfo(; name = "", boresight_rotangle_rad = 0.0, spin_boresight_angle_rad = 0.0,
               spin_rotangle_rad = 0.0, hwp_rpm = 0.0, ...)

Instrument geometry, with the same fields and defaults as InstrumentInfo in litebird_sim. The boresight-to-spin rotation is

bore2spin_quat = Rz(spin_rotangle_rad) · Ry(spin_boresight_angle_rad) · Rz(boresight_rotangle_rad)

hwp_rpm is informative only: pass an IdealHWP to the Observation to model a rotating half-wave plate.

Falcons.DetectorInfo — Type
DetectorInfo(; name = "", sampling_rate_hz = 0.0, quat = identity, pol_angle_rad = 0.0, ...)

Detector parameters, with the same fields and defaults as DetectorInfo in litebirdsim. Only name, `samplingratehz,quatandpolangle_rad` are used to compute pointings; the other fields are carried along.

quat is the rotation from the detector frame (beam along z, polarisation reference along x) to the boresight frame. It may be a Quaternion, a 4-element vector (x, y, z, w) or a RotQuaternion (constant or time-dependent); it is always stored as a RotQuaternion. See detector_quat to place a detector on the focal plane.

pol_angle_rad is the polarisation angle relative to the detector x axis. It is not added to the orientation angle ψ returned by get_pointings nor used in make_h_maps, as in litebird_sim.

detector_quat(θ, φ; ψ = 0.0) -> Quaternion

Detector-to-boresight rotation Rz(φ) · Ry(θ) · Rz(ψ) of a detector whose beam points at the focal-plane position (θ, φ) (rad, θ measured from the boresight) with its polarisation reference rotated by ψ around the beam.

Falcons.FreqChannelInfo — Type
FreqChannelInfo(; bandcenter_ghz, channel = nothing, ...)

Frequency-channel parameters, with the same fields, defaults and post-initialisation as FreqChannelInfo in litebird_sim (the bandpass object is not included):

  • channel defaults to "<bandcenter_ghz> GHz" with one decimal;
  • number_of_detectors is inferred from detector_names or detector_objs when it is 0, and missing names become det0, det1, …;
  • a zero net_channel_ukrts or net_detector_ukrts is derived from the other one with the √N scaling;
  • detector_objs are stored as UUID strings (a URL keeps its last component).

Falcons.IdealHWP — Type
IdealHWP(; ang_speed_radpsec, start_angle_rad = 0.0)

Ideal half-wave plate rotating at ang_speed_radpsec (rad/s), as IdealHWP in litebird_sim. Its mechanical angle at the time t is

χ(t) = start_angle_rad + ang_speed_radpsec · (t − t_sim)

wrapped to [−π, π], where t_sim is the start_time_simulation_s of the Observation. The angle is evaluated in closed form, so it does not accumulate rounding errors over long observations.

Falcons.Observation — Type
Observation(attitude, instrument, detectors; start_time_s, duration_s, hwp = nothing,
            start_time_simulation_s = start_time_s, spin_perturbation = nothing,
            delta_time_s = nothing)

A continuous stretch of observation by a set of detectors, the counterpart of an Observation in litebird_sim without the TOD.

  • attitude: the rotation from the spin-axis frame to Ecliptic coordinates. Either a SpinningScanningStrategy (evaluated analytically) or a time-dependent RotQuaternion, e.g. a measured attitude converted to this frame by the user.
  • instrument: an InstrumentInfo giving the boresight-to-spin rotation.
  • detectors: a DetectorInfo or a vector of them. All detectors must share the same sampling_rate_hz.
  • start_time_s: absolute time of the first sample (s). Spin, precession and the anti-Sun direction are evaluated at absolute times, as litebird_sim does for a floating-point start time.
  • duration_s: the observation has floor(sampling_rate_hz * duration_s) samples at start_time_s + k / sampling_rate_hz.
  • hwp: an IdealHWP, or nothing.
  • start_time_simulation_s: origin of the HWP phase. Observations split from the same simulation share it, so the HWP angle is continuous across them.
  • spin_perturbation: optional RotQuaternion multiplied on the right of the spin-to-Ecliptic rotation, i.e. a rotation expressed in the spin-axis frame (the position of SpacecraftCoord in litebird_sim).
  • delta_time_s: nothing computes every sample exactly. A number reproduces litebirdsim: the boresight rotation is computed on anchors every `deltatimesseconds fromstarttimesimulations` and interpolated with slerp.

The detector quaternion at a sample is

q(t) = A(t) · S(t) · bore2spin · d(t)

with A the attitude, S the spin perturbation and d the detector quaternion; time series are interpolated to t.

Rotations

Falcons.Quaternion — Type
Quaternion{T}(x, y, z, w)

Quaternion with vector part (x, y, z) and scalar part w, stored in the same (x, y, z, w) order as litebird_sim and as the quat entries of the IMO.

Products follow the Hamilton convention and rotations are active: the vector v is rotated to q v q* (see rotate_vector). The type is isbits, so it can be passed to GPU kernels.

Quaternion(x, y, z, w) promotes the components to a common floating-point type, so Quaternion(0, 0, 0, 1) is a Quaternion{Float64}.

Falcons.RotQuaternion — Type
RotQuaternion(q::Quaternion)
RotQuaternion(quats::AbstractVector{<:Quaternion}; start_time_s, sampling_rate_hz)
RotQuaternion(quats::AbstractMatrix; start_time_s, sampling_rate_hz)

A rotation that is either constant or sampled in time, as RotQuaternion in litebird_sim.

A time series holds the quaternions quats[k] at the absolute times start_time_s + (k - 1) / sampling_rate_hz (s); values in between are obtained by spherical linear interpolation (slerp). Asking for a time outside the covered range throws an ArgumentError. A matrix argument must have 4 rows, one quaternion (x, y, z, w) per column. Quaternions are normalised on construction.

quat * r and r * quat with a constant Quaternion apply it to every sample; the product of two time series requires the same time grid.

Pointings and maps

Falcons.get_pointings — Function
get_pointings(obs; detector_idx = :all, output_coordinate_system = Ecliptic,
              backend = CPUBackend()) -> (pointings, hwp_angle)

Pointings of the detectors of obs, as Observation.get_pointings in litebird_sim.

pointings[:, k, i] holds (θ, φ, ψ) (rad) of the i-th selected detector at the k-th sample: colatitude, longitude in [0, 2π) and orientation angle in (−π, π] (see compute_pointing_and_orientation). With detector_idx = :all or a vector of (1-based) indices the array has size (3, n_samples, n_detectors); with an integer it has size (3, n_samples). The memory layout is the same as litebirdsim's `(ndetectors, n_samples, 3)`.

hwp_angle is the HWP angle of every sample, or nothing without an HWP.

Falcons.make_h_maps — Function
make_h_maps(observations; nside, n_m_couples = [(0, 0), (2, 0), (4, 0)],
            output_coordinate_system = Galactic, backend = CPUBackend()) -> HMapsResult

h-maps of every detector, as make_h_maps in litebirdsim (see HMapsResult). observations is an Observation or a vector of them; samples of the same detector (matched by name) are accumulated over all observations before normalising. `nmcouplesis a vector of integer(n, m)tuples or an(N, 2)matrix; see [nmgrid`](@ref).

Pointings are computed in chunks and never stored in full.

source
Falcons.HMapsResult — Type
HMapsResult

Spin moments ("h-maps") of the scan, as returned by make_h_maps:

h_{n,m}(p) = (1 / N_p) Σ_{samples in p} exp(+i (n ψ + m χ))

with ψ the orientation angle (without the detector polarisation angle) and χ the HWP angle, as make_h_maps in litebirdsim. For (n, m) = (0, 0) the real part holds the hit count `Np` instead; pixels without hits are 0.

Fields:

  • h: (n_couples, n_pixels, n_detectors) ComplexF64 array (RING ordering).
  • n_m_couples: the (n, m) pairs, in the order of the first axis of h.
  • detectors: detector names, in the order of the last axis of h.
  • hits: (n_pixels, n_detectors) hit counts, or nothing when read from a file without the (0, 0) couple.
  • nside, coordinate_system, duration_s (the sum of the time spans of the observations; one value for all the detectors, as in litebirdsim), `samplingratehz,detectorsplitandtime_split(always"full"`).

Use h_map and hitmap to access a single map.

Falcons.save_h_maps — Function
save_h_maps(res::HMapsResult, output_directory) -> Vector{String}

Write one HDF5 file per detector, h_maps_det_<name>.h5, in the layout used by save_h_maps in litebirdsim: root attributes `coordinatesystem,det,detectorsplit,timesplit,durationsandsamplingrate_Hz, and one group"n,m"per couple holding the datasetsReandIm(RING ordering). Falcons.GPUBackend — Type
GPUBackend(; num_gpus = 1, gpu_ids = nothing)

Compute on CUDA GPUs in Float64. Requires using CUDA (which loads the FalconsCUDAExt extension). gpu_ids selects devices by their 0-based ids; otherwise the first num_gpus devices are used, splitting the samples between them. IMO and parameter-file functions

Falcons.Imo — Type
Imo(flatfile_location)

Instrument model database read from a local flat file, as Imo in litebirdsim (through libinsdb). `flatfilelocationis either a directory containingschema.jsonor the path of the schema file itself. Only uncompressed JSON is supported: decompressschema.json.gz` first.

Query objects with query, or build parameters directly with DetectorInfo(imo, url), FreqChannelInfo(imo, url), InstrumentInfo(imo, url) and SpinningScanningStrategy(imo, url).

source
Falcons.query — Function
query(imo, identifier) -> DataFile | Quantity | Entity | FormatSpecification

Look up an object of the IMO, as Imo.query in litebird_sim. identifier is

  • a UUID string, or "/data_files/<uuid>": a data file;
  • "/quantities/<uuid>", "/entities/<uuid>" or "/format_specs/<uuid>": a quantity, an entity or a format specification;
  • a release path "/releases/<tag>/<entity>/…/<quantity>" (the /releases prefix is optional): the data file of that quantity included in the release.

If a release contains several versions of the quantity, the one with the latest upload_date is returned (the dates are compared as ISO 8601 strings, so they must share the same format), and equal dates throw an ArgumentError. litebird_sim (libinsdb) returns any one of them instead.

Falcons.DataFile — Type
DataFile

A version of a quantity in the IMO: uuid, name, metadata (the dictionary the DetectorInfo(imo, url)-style constructors read), owning quantity UUID, upload_date, spec_version and the release_tags it belongs to.

Falcons.detector_list_from_parameters — Function
detector_list_from_parameters(imo, definitions) -> Vector{DetectorInfo}

Build detectors from a list of dictionaries, e.g. the [[detectors]] tables of a parameter file, as detector_list_from_parameters in litebird_sim. Each entry is one of

  • channel_info_obj = url: the detectors of a channel, optionally only the first num_of_detectors_from_channel (all of them if the channel has fewer, as in litebirdsim; a negative number throws an ArgumentError), or a single boresight detector named `detectornamewhenuseonlyoneboresightdetector = true`;
  • detector_info_obj = url: one detector from the IMO;
  • neither: a default DetectorInfo.

Any DetectorInfo field given in an entry (other than with channel_info_obj) overrides the value read from the IMO.

Falcons.run_h_maps_pipeline — Function
run_h_maps_pipeline(parameter_file) -> HMapsResult

Compute and save h-maps from a TOML parameter file whose keys follow litebird_sim's names:

[simulation]
base_path = "output"           # output root
start_time = 0.0               # s
duration_s = "1 year"          # seconds, or "N years/days/hours/min/s"

[imo]                          # optional
flatfile_location = "/path/to/imo"

[scanning_strategy]
imo_url = "/releases/<tag>/…/scanning_parameters"
# or spin_sun_angle_rad, precession_rate_hz, spin_rate_hz
# delta_time_s = 2.0           # optional: interpolate as litebird_sim

[instrument]
imo_url = "/releases/<tag>/…/instrument_info"
# or boresight_rotangle_rad, spin_boresight_angle_rad, spin_rotangle_rad

[hwp]                          # optional
ang_speed_radpsec = 4.817      # 2π · rpm / 60
start_angle_rad = 0.0

[[detectors]]                  # see detector_list_from_parameters
channel_info_obj = "/releases/<tag>/…/channel_info"

[h_maps]
nside = 128
n_m_couples = [[0, 0], [2, 0], [4, 0]]
output_coordinate_system = "Galactic"
output_directory = "h_maps"    # relative to base_path

The maps are written with save_h_maps, one file per detector.
